# 如何添加

点击「添加 VRM 模型」，直接选择一个 `.vrm` 文件。检查成功后自动加入模型列表并切换，无需解压或逐项配置；原有模型和设置保留。

模型卡片的「移除」会在确认后清理列表项、动作映射和程序管理的导入副本，保留原始 VRM。移除当前模型后不显示角色；微光也不会在重启时重新添加。更新模型可先导入新文件，检查后移除旧项。

支持 **VRM 0 和 VRM 1**。模型、贴图及动作数据必须包含在文件内，不接受外部 buffer 或贴图引用。Blender 工程、FBX 和 Unity `.anim` 请先在模型编辑工具中转换、导出。

# 人形骨骼

按 VRM 的 **Humanoid 映射**识别骨骼，不要求 Blender 对象或骨骼使用固定名称。导出前请将髋、脊柱、头、双臂和手、双腿和脚映射到以下 15 个字段：

```text
hips, spine, head
leftUpperArm, leftLowerArm, leftHand
rightUpperArm, rightLowerArm, rightHand
leftUpperLeg, leftLowerLeg, leftFoot
rightUpperLeg, rightLowerLeg, rightFoot
```

肩、胸、颈、脚趾、眼睛和手指可选，按模型已提供的标准映射识别。缺少手指映射时，不能自动补出手指动画。

# 眨眼与光标跟随

眨眼是可选功能。没有闭眼表达的模型仍可导入，使用基础待机、轻呼吸和头部跟随，只是不自动眨眼。启用眨眼需在 VRM 中注册以下表达之一：

- **VRM 0**：`presetName: "blink"`，或同时提供 `blink_l` 和 `blink_r`。
- **VRM 1**：`expressions.preset.blink`，或同时提供 `blinkLeft` 和 `blinkRight`。

表达需绑定真实的闭眼形态键（morph target），并有非零权重。形态键名称可以自定；空表达、零权重或仅有单侧闭眼表达时，不启用自动眨眼。已声明的绑定必须有效；引用不存在的网格或形态键仍会拒绝导入。

头部提供限角光标跟随。**眼球跟随为可选功能**，需要正确配置 VRM `lookAt`，使用眼骨或视线表达驱动眼睛；没有相应配置时，眼球不会独立转动。

# 基础待机与其他动作

没有动作也可以导入。程序自带 `StarLiteIdle`，提供放松站姿和轻呼吸，并自动配置为待机。模型有名为 `Idle` 的动作时优先选用它；角色配置的 `neutralAnimation` 或明确提供的默认映射可指定自己的基础动作，也可在设置中更换。

基础待机通过标准人形骨骼重定向，效果受模型比例和权重影响。其最终姿态与烘焙由 StarCried 制作，包含 Warudo `Human@SM Breathe` 呼吸层。

模型内嵌的标准 glTF 动作会自动列出。建议使用**唯一英文名称**，名称区分大小写；`StarLiteIdle` 为程序保留名称。

- **待机**：循环播放，默认已配置。
- **工作中（含思考）、完成、出错、遇到阻碍、等待确认**：可选，播放一次后回待机；新状态可打断。
- **点击回应、偶发小动作**：可多选，每次随机播放一个。未选择则不触发，工作期间也不会触发。

程序只自带基础待机，不会生成挥手、工作等其他动作。映射修改后自动保存。

# 许可与本地文件

导入只在本机建立副本，不上传或修改源文件。检查失败时保留当前模型。

模型作者和许可从 VRM 元数据读取，可通过模型卡片的「查看许可」查阅。请确认拥有模型、贴图和动作的使用权限；没有许可信息不代表可以自由使用。
