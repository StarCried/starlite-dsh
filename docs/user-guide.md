# StarLite for DSH 安装与使用

本指南供 Windows 11 x64 + WSL2 DSH 用户使用。Windows 负责角色显示，WSL 负责 DSH；无需再启动一份 Windows DSH。当前新名称尚未发布，先使用本地候选文件验收，不要把下面的候选版本号当作已上架的 npm 版本。

## 1. 安装 Windows 桌宠

取得同版本的 `StarLite for DSH_0.1.0-alpha.0_x64-setup.exe`、`dsh-starlite-0.1.0-alpha.0.tgz` 和作者提供的 `SHA256SUMS`。正式发布后从作者发布页取得；新命名安装器将在候选验收阶段本地构建，本轮尚未生成。

在 PowerShell 核对安装包和插件的 SHA-256：

```powershell
Get-FileHash -Algorithm SHA256 "C:\Downloads\StarLite for DSH_0.1.0-alpha.0_x64-setup.exe"
Get-FileHash -Algorithm SHA256 "C:\Downloads\dsh-starlite-0.1.0-alpha.0.tgz"
```

将示例路径换成实际文件。Alpha 安装包未签名，Windows 可能显示 SmartScreen；核对来源和哈希后按系统提示处理，不关闭系统防护。安装为当前用户。首次打开时选择独立授权的微光 ZIP，确认许可后自动导入模型、动作和状态映射，无需解压或逐项配置。程序不内置微光或第三方动作。

## 2. 给已有 DSH 安装插件

在 **WSL 终端**执行。已有 DSH 时先检查 `dsh --version`；本项目已有契约验收记录对应 `0.1.5-rc.1`，升级 DSH 后仍需重新核对兼容性。没有 DSH 时可安装该版本：

```bash
npm install -g --prefix "$HOME/.local" @deepseek-ai/dsh@0.1.5-rc.1
export PATH="$HOME/.local/bin:$PATH"
```

使用自己日常启动的 profile；本例为 `web`。本地候选安装：

```bash
dsh plugin --profile web add /mnt/c/Downloads/dsh-starlite-0.1.0-alpha.0.tgz
```

路径需换成实际 tarball 的 WSL 绝对路径。正式 npm 发布后，才可改用 `dsh plugin --profile web add dsh-starlite@<已发布版本>`。普通用户无需安装 pnpm、Rust 或 Blender。

如果这个 profile 装过旧名桥接包，先执行下面的移除命令，再安装新名包，避免同时运行两份桥接：

```bash
dsh plugin --profile web remove dsh-inochi2d-pet
```

这一步只移除旧桥接插件，不删除桌宠用户模型与设置。不要编辑插件缓存，也不要把临时认证链接写入配置。此文档整理阶段不会自动替换你当前运行的插件或安装包。

在 DSH 的「设置 → 插件 → 插件列表 → 全局」中查找 `dsh-starlite`。默认的「插件配置」页只展示带网页配置卡的插件；桌宠设置在 Windows 程序里。安装后重新打开设置刷新清单。

## 3. 资源包自动导入

从 Windows 托盘打开「设置」：

点击「导入资源包 ZIP · 自动配置」，选择作者提供的独立资源 ZIP。阅读许可并点击「同意许可并自动导入」后即可使用，无需解压、单选模型与动作、手填映射或再次保存。取消或检查失败保留当前模型和设置。

导入使用包内的桌面模型、动作、角色配置和作者预设映射；已有显示、隐私和气泡偏好保留。首次使用默认 30 FPS／DPR 1.5，可在设置中调整。包内哈希、资源结构与动作映射会一起检查。

当前标准 VRM 可以不带动作做独立预览，但桌宠保存仍要求真实 Idle。程序自带的通用 Idle、无动作模型的自然站姿和轻呼吸尚待下一阶段实现。标准人形骨骼、可用的眨眼表达和正确的 lookAt 映射分别决定动作重定向、眨眼和眼球跟随效果。

更换自己的 `.vrm`、外部 `.vrma` 或可选 Inochi2D `.inp` 时，使用设置中的单文件入口，见 [模型导入](model-import.md)。无需手工修改程序保存的设置 JSON。

## 4. 日常启动与互动

日常只需在 WSL 启动：

```bash
dsh --profile web
```

把 `export PATH="$HOME/.local/bin:$PATH"` 加入自己的 shell 启动文件后即可直接运行。插件会通过 Windows 互操作与已注册启动协议拉起桌宠；没有导入模型时显示设置。缺少 Windows 程序或契约不兼容时只停用桌宠，不阻止 DSH 运行。

- **拖动／设置**：拖动模型身体；周围透明区域点击穿透。右键身体或托盘打开设置；手动全窗口穿透开启后，用托盘恢复操作。
- **单击**：待机时随机回应并显示官方 DeepSeek 余额与今日 DSH 费用估算；工作时只查费用。等待答题时费用不会覆盖表单。
- **双击**：打开气泡显示的会话；没有会话时打开 DSH Web UI 首页。断线或引用失效时显示不可用，不跳到其他会话。
- **气泡**：默认精简模式为会话标题＋当前状态；详细模式额外显示经过限制的思考／输出内容。普通用户问题可在气泡内单选、多选或输入文字；工具权限审批继续在 DSH 处理。
- **动作**：只有待机循环。其余状态动作各播放一次再回待机；逻辑任务仍忙碌时不会触发点击或偶发动作。思考和输出共用工作动作，新状态可打断旧动作。
- **隐私**：隐私模式显示固定状态，隐藏会话内容与输入题目；不把用户提示、工具参数／结果、真实会话 ID 或 API Key 发送给 Windows。

桥接随 DSH 销毁；Windows 桌宠是独立进程，断连后隐藏，等待 60 秒重连后退出。失去心跳时先经过最多 45 秒检测。当前只支持 WSL2 DSH；关闭 WSL 互操作或缺少启动协议会影响自动启动。

## 费用信息

在 DSH「模型」页面配置官方 DeepSeek 凭据即可，桌宠不要求填写 API Key。支持默认 `deepseek-official` 和可选 `deepseek` 路由；两者都有凭据时显示默认路由的余额。余额仅在用户查询时调用官方只读接口，缓存 60 秒，不发起付费模型请求。

同一账户配置多个官方模型时共用余额，用量按实际请求模型估算。多个账户时，余额卡标明所用配置；今日估算仍包含当前 profile 的可用官方路由记录，不能视作单个账户账单。更换 key 前的历史记录也无法可靠归属到新账户。未知模型、网关、缺失用量或读取不完整会显示限制，不伪造金额；其他厂商费用暂不查询。

当前费率区间由单独徽标显示。金额范围覆盖高峰／空闲价格差异，是 DSH 用量估算，不是账户的官方账单；未完成请求和其他应用不包含在内。

## 升级与卸载

升级时停止该 DSH profile，安装同版本的新 Windows 程序和桥接包，再重新启动。已有模型、映射与偏好沿用；本轮保留原生安装标识、可执行文件名、启动协议和用户数据目录。新旧桥接包不能同时安装到同一 profile。

卸载桥接：

```bash
dsh plugin --profile web remove dsh-starlite
```

然后在 Windows「已安装的应用」中卸载 StarLite for DSH。用户模型与设置是否删除是独立选择，删除前确认是否要保留。模型资源包另有许可，程序卸载不改变其使用约定。

## 常见情况

- **没有自动出现**：确认启动的是安装插件的 profile、Windows 程序已安装、WSL 互操作可用；在托盘打开设置核对模型。
- **没有动作可选**：VRM 不等于动作包；当前需另选 `.vrma`，且 Idle 必填。一般 FBX 或任意 GLB 不属于该导入入口。
- **没有眼球或眨眼变化**：检查模型的 VRM lookAt 与 blink 表达；程序不能从缺失映射推断完整面部行为。
- **安装同路径 tarball 后仍是旧代码**：候选验证应核对内容哈希；同版本同路径可能命中包缓存。正式升级使用新的版本，不编辑缓存文件。
- **余额未配置／不可用**：检查 DSH 的官方端点与凭据配置；网关或不支持的服务契约不会触发余额请求。
