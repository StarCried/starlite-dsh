# 模型导入与动画约定

桌宠接受 Inochi Creator 导出的 `.inp`，或 `.vrm` 加外部 `.vrma` 动作和可选角色配置。导入器按后端检查资源、兼容性和动画清单，在应用数据目录中创建独立副本。检查、构建、复检和配置写入全部成功后才切换模型。

## 导入自己的 VRM

右键点击桌宠身体可打开设置；托盘“设置…”入口同样可用。

1. 准备包含贴图的 VRM 0 或 VRM 1 文件。外部贴图和外部 buffer 引用会被拒绝；不要直接选择 Blender 母版或 FBX。
2. 准备独立的 VRMA 动作文件。它们需要标准 humanoid 骨骼映射；Unity `.anim` 和 FBX 不能在桌宠中直接播放，先在自己的编辑工具中重定向、烘焙并导出 VRMA。
3. 在设置中选择模型，再多选 VRMA 文件。文件名用于动作名，因此同一次导入不要使用重名文件。检查完成后核对实际动作列表。
4. 普通 VRM 无需角色配置。微光专属配置仅描述其表情、眨眼、耳朵和配饰；不要套用到别的角色。
5. 明确选择 Idle，并为其他状态选择动作或“禁用”。Click 和 Ambient 可多选。没有动作的 VRM 可在独立播放器预览，但桌宠保存仍需要有效 Idle。
6. 保存后分别检查手指、曲腿、表情、弹簧骨骼、大动作边界和中途切换。不同身材的重定向效果需要在自己的动画工程中调整，不能只凭动作列表存在就判断匹配正确。

VRM 首次配置默认 30 FPS、DPR 上限 1.5；按本机表现调整。默认待机跟随
光标，其他动作保留作者的视线方向。导入只建立本机副本，不会公开模型。

## 动画映射

| 状态 | 是否必填 | 播放方式 | 结束条件 |
|---|---:|---|---|
| Idle | 是 | 循环 | 进入其他状态 |
| Working（含思考） | 否 | 单次 | 片段结束回 Idle；其他工作状态立即替换它 |
| Approval | 否 | 单次 | 片段结束回 Idle；批准气泡保留到请求解除 |
| Blocked | 否 | 单次 | 片段结束回 Idle；阻塞状态保留到下一次 turn 开始 |
| Completed | 否 | 单次 | 片段结束回 Idle；完成气泡保留 6 秒 |
| Error | 否 | 单次 | 片段结束回 Idle；错误气泡保留 8 秒 |
| Click | 否 | 单次 | 只允许 Idle 点击；播放后恢复 Idle |
| Ambient | 否 | 单次 | Idle 中每 60–120 秒随机播放；播放后恢复 Idle |

Click 与 Ambient 可以多选，每次从各自列表中等概率抽取一个，不连续播放整个列表。空列表禁用该交互。暂停、隐藏、断连和切换模型取消偶发动作计时；恢复后重新计时。工作状态可以打断小动作和点击回应。

设置版本 3 将旧单个 Click 转成列表，并合并 Thinking 到 Working（已设置 Working 时优先保留它）。DSH 事件协议仍可区分思考和工具执行，桌宠只显示同一个工作动作，二者切换不重启动作。

逻辑状态仍忙碌时，回到 Idle 动画也不会允许点击或偶发小动作。新的工作状态立即替换旧动作，旧片段的迟到完成不会覆盖新状态。

点击模型身体可查看官方 DeepSeek 余额和今日 DSH 费用估算。工作中点击只查询费用，不启动点击动作；费用显示 10 秒后恢复最新工作文字。任务状态变化、断连或开启隐私模式会立即收回费用气泡。余额暂存 60 秒，今日金额是按本地会话用量和高峰/空闲价格计算的区间，并明确显示部分记录或未计价请求；它不包含其他程序的消费。没有可用数据时显示“暂不可用”，不显示虚构的零费用。

映射使用精确动画名，区分大小写。可选项选择“禁用”后停止动画并保留模型中性姿态，不会隐式选择 Idle，也不会由网页程序模拟肢体动作。尾巴、呼吸、头发和袖子等应由模型自身动作与物理完成。

建议模型作者使用上表中的英文名称，以便导入向导自动预选；这只是命名约定，不是强制参数规范。不同模型可以保留自己的参数范围和动画设计，用户在下拉框中完成映射。

## 失败与授权

下列情况会阻止导入：文件损坏、资源越界、不支持的模型功能、准备过程异常、缺少 Idle、映射名称不存在或准备后复检失败。失败不会删除或覆盖当前可用模型。

模型只存储在本机，不上传、不遥测。导入功能不改变模型版权；用户必须自行确认使用权。公开安装包内的“微光”演示模型必须在 `assets/microlight/ASSET_LICENSE.md` 中提供独立、明确、可再分发的授权，否则发布检查必然失败。

模型、贴图与动作可能属于不同权利人。外部 VRMA、呼吸叠加、手势和经过
重定向或烘焙的动作也需要各自的使用与分发许可；自己的角色模型授权不能
代替第三方动作授权。公开演示资源应记录每个来源、文件哈希、授权与署名。
